# Changelog

One line per change, newest group first. Add your line in the same commit as the change.

## Unreleased

- Pipeline `original.mpr` on an MPR v2 app (GM-8): `write_original` in `bin/cloud/upgrade-pipeline.sh` writes it with `git archive` of the .mpr and its `mprcontents/` (beside it in the run folder) instead of `git show rev:App.mpr`, which has no units on v2 and made impact_map, crosscalls --own, action_inventory and journey_scope read nothing quietly. `bin/mprmodel.py` now exits with a message when a v2 .mpr has no `mprcontents/` beside it, never an empty model; v1 unchanged. Controls mprmodel-v2-without-mprcontents-catch, mprmodel-v2-with-mprcontents-pass, mprmodel-v1-unchanged-pass, pipeline-original-v2-mprcontents-catch, pipeline-original-v1-pass; built on a v2 copy of the synthetic model, a field run on a real v2 app is still owed. An empty `mprcontents/` is refused too; the journey tools (run_journeys, process_journeys, gen_journeys) treat the refusal like any unreadable model (a note or a failed verdict, not a crash). A v2 run started before this change must rerun with `--only fetch` (or `--from fetch`) to rewrite `original.mpr`.
- Toolkit paths and setup writes (DV-1): SKILL.md and steps/triage.md no longer point at a sibling checkout under the home folder; `TK` is the folder that holds SKILL.md and `B=$TK/bin`. `bin/setup-container.sh` prints "This setup writes outside the run folder:" before it changes anything (old-style `~/Mendix` link, dockerd start or not, docker images, the Maven cache jar, the mxcli source build folder, Playwright folder, auth file, system and pip packages), built from the script's own variables; `--plan` prints only that list and exits 0 without making any folder. What setup does is unchanged. Related SETUP-1 and GM-3 stay as they were. Controls: docs-no-sibling-toolkit-path-catch, docs-toolkit-path-from-skill-folder-pass, setup-plan-lists-outside-writes-pass, setup-plan-changes-nothing-pass, setup-plan-follows-variables-pass, setup-plan-no-args-refused-pass.
- SETUP-PROMPT.md has a run-mode switch (DV-7): the unattended text stays the default; a marked attended block stops at the proposal sign-off (pipeline exit 14, cockpit sign-in) and tells the agent never to sign, answer or pause for the owner. New `controls/setup_prompt_control.sh` checks both variants and that everything the attended block names exists.
- Which company brain a run uses is now printed (DV-3): `bin/brainpath.py --describe` prints one line, `brain: <path> (from UPG_BRAIN|local.env|tools folder)` or `brain: none found (looked: ...) - set UPG_BRAIN=<path>`; the pipeline prints it at triage (and keeps it in `$WORK/brain.txt`), `gate-summary.md` carries it after the Changes/heal lines, and steps/triage.md tells the agent to quote it. The search order is unchanged. Controls: brainpath-describe-none-catch, brainpath-describe-bad-upg-brain-catch, brainpath-describe-upg-brain-pass, brainpath-describe-local-env-pass, brainpath-describe-tools-folder-pass, brainpath-plain-order-unchanged-pass, gate-summary-brain-none-catch, gate-summary-brain-found-pass, pipeline-triage-brain-crash-continues-catch.
- Sign-off card lists which rows the "n choices were assumed by the agent" count is made of (DV-13): D-id with its text, P-id with the choice, or the assumed steps; one list gives both the count and the card, HTML-escaped, first 5 then "+k more" linking the matrix. Controls: cockpit-signoff-names-the-assumed-d-row-catch, cockpit-signoff-count-equals-listed-mixed-pass, cockpit-signoff-assumed-list-capped-pass.
- Resume gap in DV-6 closed: `step_baseline` runs `buildout.py exclude` itself (idempotent, `note` on failure), so a run resumed with `--from baseline` or `--only baseline` on an app whose run start predates the exclude gets it too; steps/baseline.md item 0 says so. Control: buildout-baseline-step-adds-exclude-catch.
- Baseline build output no longer dirties the app tree (DV-6, MC-3): new `bin/buildout.py` (`exclude` appends `.classpath`, `.project`, `*.launch` to `.git/info/exclude`, idempotent; `check` lists ACCEPTED vs OTHER dirty paths); the pipeline baseline runs it before the old build, `convertpre.py` and triage item 9 accept exactly those paths plus the tracked `theme-cache/**` and still refuse any other dirty file. Controls: buildout-baseline-output-pass, buildout-exclude-idempotent-pass, buildout-check-accepted-pass, convertpre-build-output-pass, convertpre-source-edit-catch, buildout-check-source-edit-catch, buildout-lookalike-prefix-catch, buildout-rename-out-of-cache-catch, buildout-nested-classpath-catch, buildout-tracked-project-catch.
- FEEDBACK register: DV-9 (PR #99) and DV-11 (PR #100) marked fixed with their controls; new open row DV-15 (a step skipped on purpose blocks every later `--from`; owner decision), found in the PR #99 review.
- Cockpit on a headless host (DV-4, DV-10): `cockpit_live` starts the cockpit server (and writes `.cockpit-work`) whether or not a browser opener exists, and logs `cockpit: server up at URL` or `cockpit: no cockpit is running: REASON`; only the browser-open needs an opener. The start logic is one script, `bin/cloud/cockpit-up.sh` (idempotent, never a second server for the folder), which `resume.sh` also runs for every run folder with a work folder; the pipeline's "docker daemon not running" message now names `bin/cloud/resume.sh <run folder>`. Controls: cockpit-live-no-opener-starts-server-catch, cockpit-live-no-opener-forced-starts-server-catch, cockpit-live-server-failure-is-logged-catch, pipeline-docker-down-message-names-resume-catch, resume-starts-cockpit-once-catch.
- Proposal: agent notes survive a propose rerun (DV-11). The agent writes notes to `$W/AGENT-NOTES.md`, a file propose only reads; PROPOSAL.md shows them in an `## Agent notes` section before the sign-off (outside the plan hash, so a note never clears a signature) and the cockpit shows them in the plan drawer under "Agent notes". Notes written into PROPOSAL.md itself were lost on the next rerun. Controls: proposal-agent-notes-*, proposal-no-agent-notes-no-section-pass.
- Pipeline `--from STEP` no longer runs steps before STEP (DV-9: `--from propose` re-ran basewalk): an earlier step that is not done and that STEP builds on refuses the run (exit 2, nothing changed), names the steps and advises a rerun without `--from` (done markers skip finished steps) or `--only STEP`; heal and apidirect, when not done, are skipped and named in the output. Controls: pipeline-from-skips-earlier-undone-catch, pipeline-from-skips-optional-undone-pass.
- Cockpit `/status` (DV-14): returns `{"state":"idle","reason":"no-work-dir"}` or `{"state":"idle","reason":"no-step-running"}` instead of null, so "nothing running" can be told from "no server state"; a running step's payload is unchanged and the live page hides its Running-now bar on idle as it did on null. Controls: cockpit-status-idle-says-why-catch, cockpit-status-running-keeps-payload-pass.
